KERNEL R/W PRIMITIVE (corrected):
  NOT EkIKZR. NOT JNI. Instead:
  Hx1400.kread()/kwrite() build ROP chains in gSTACK, then fire kevent()
  on the hijacked kqueue. The ROP executes in kernel context and performs
  the actual kernel memory access. Each kread/kwrite = one kevent round-trip.

WHERE DOES P[] COME FROM?
  - P[] is set EXTERNALLY by InitXlet via Boot.exec VM opcode 13 (setFieldValue)
  - The data comes from bonk/local/*.bin template files (rules.bin, shapes.bin,
    guards.bin, schedule.bin, template-hashes.bin, marker-sites.bin, write-sites.bin)
  - Hx1400.class is SHA-256 frozen in InitXlet.CLASSES[][] so it cannot be
    modified — but P[] lives outside the hash-check, so FW 14.00 values can be
    swapped in at runtime via reflection
  - tableFault() defensively returns "P missing or wrong length" if the caller
    didn't populate P[] first

GRVA/GLEN/GNOW/GNEW (guard tables):
  GRVA[] = kernel addresses of guard sites (patched kernel functions)
  GLEN[] = byte length at each site
  GNOW[] = current bytes (stock firmware)
  GNEW[] = patched bytes (HEN-modified)
  Before applying 1400.bin, phase H checks all sites:
    if ALL stock    → apply 1400.bin
    if ALL patched  → skip (already HENed)
    if MIXED        → refuse, demand cold reboot (per NOTICE.txt)
